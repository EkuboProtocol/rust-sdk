# Contract conformance vectors

Local fixture vectors for `ZeroSeedLaunch` at `EkuboProtocol/evm-contracts@39ca1918e4d16b1c9fd4db5ed70761ef7b12c6ae` (tree `b95e748486d5bbf23635fcea73bd4825b3a36455`), against the Q0.64-fee `Core` built at that commit (runtime keccak `0xc5f90c9d0dbc5037f8f9e248f4bb292e7c1824f584eb6550cb4cad525b38c71a`). They are not live evidence.

The parity vectors hold only values read from the local `Core` and extension: `LaunchCreated` and `LaunchSwapped` event fields, `Core.poolState` before and after every forwarded swap, the creator fee ledger, `feeAt`, revert data and in-test gas. `tests/zero_seed_launch_vectors.rs` builds each pool from the `LaunchCreated` fields and its `Core` state, then chains the SDK's own post-swap state through every step and requires it to equal `Core`'s at the same block timestamp.

Regenerate:

```sh
git -C <evm-contracts> worktree add --detach /tmp/zs 39ca1918e4d16b1c9fd4db5ed70761ef7b12c6ae
cp -r <evm-contracts>/lib/forge-std <evm-contracts>/lib/solady /tmp/zs/lib/
cp tests/vectors/generator/ZeroSeedLaunchSdkParity.t.sol /tmp/zs/test/extensions/
(cd /tmp/zs && forge test --offline --match-contract ZeroSeedLaunchSdkParity -vv) \
  | python3 tests/vectors/generator/parity_to_json.py > tests/vectors/zero-seed-launch-parity.json
```

Forge output is deterministic, so the file is reproduced byte for byte. `generator/mutants.py` applies 15 mutations to `src/quoting/pools/zero_seed_launch.rs` and requires the vector tests to fail for each.
